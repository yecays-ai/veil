# S11 第 3 张：备份一致性协调核心

基于 main 提交：`c813d48fa96594d216e9cce1c323d45af8f0a8a3`，正式仓库 `yecays-ai/veil`。

【这一刀只解决】提供跨域逻辑写入与快照读取的协作互斥协议。
【验收话】无手机入口；模拟并行写入全部完成后才允许读取，读取期间后续写入等待，失败后锁释放。
【做完划掉】仅协调核心；S11 全站备份与恢复仍未验收。
【不做】业务写入接入、正式导出入口、恢复、UI、在线系统及 Memory。
【停止条件】定向及提交前全量检查通过，提交独立 PR 后停止；不合并或启动下一张。

## 当前事实与能力边界

第 2 张每库使用一个 readonly 事务，但四库七键之间没有全局事务。现有业务写入没有调用本协议。因此**此 PR 不提供活动设备的一致快照保证**，现有 `exportStaticBackup` 继续仅适用于静止输入。本模块没有应用调用者，不改存储结构、数据、页面或业务逻辑。

`BackupCoordinator` 接收显式传入的 Web Locks manager，无默认 navigator 访问。所有参与窗口必须使用同一 origin 的固定锁名 `veil.persistence.snapshot.v1`。跨 origin 的设备或站点不共享此锁。

- `withWrite(operation)` 使用 shared 锁：写入可以并行，但快照必须等待所有已开始的写入完成。operation 必须包住整项逻辑变更，从第一处写入到最后一处跨域提交、图片清理或回退结束；Promise 不得提前返回。不得在其内部再次取得 snapshot 锁。
- `withSnapshot(operation)` 使用 exclusive 锁：等待已有参与者写入完成，并阻止新参与者写入及其他快照，直到读取 Promise 完成或失败。未来接入时，读取七键、四库和图片的完整阶段必须在此边界内。
- 不使用本协议的写入不会被阻止。仅锁住导出函数不足以解决一致性；后续独立接入工单必须覆盖所有写入入口、跨窗口和长任务后续提交，特别是正在开发的在线系统。在覆盖核验完成前不能开放正式备份入口。
- 默认最多等待锁 30 秒，可指定 1–300,000 毫秒。等待超时或等待期间取消会撤销排队请求，回调不执行，不能稍后生成成功包。不自动重试、不强占其他窗口的锁。
- 获取锁后，等待计时器和取消监听立即清理。取消等待不能强制结束正在运行的 operation；必须等其 settle 才释放锁，避免后台工作尚未完成而互斥失效。调用者若需要取消工作，应在 operation 内完成自己的安全退出。
- 无 Web Locks、获取失败、参数错误、取消及超时均明确失败，无本地假锁回退；锁获取错误不回显原生异常内容。operation 自身失败原样传给调用者，并由 Web Locks 在回调结束时释放锁。

不新增数据库、存储版本、修订计数或依赖；不通过重复读取猜测一个跨库原子时点。使用原生跨窗口锁协议，保留现有存储结构。

## 验证边界

测试使用内存模拟锁 manager，验证协议排队、并行写入、失败释放和等待撤销；不访问真实浏览器或用户数据。Safari/iOS 原生 Web Locks、窗口终止时释放和业务完整接入尚未验收。不支持 Web Locks 的环境未来需要明确禁用此入口或另行批准替代方案，当前不会降级为不可靠的成功备份。
