## 做什么

- `/settings/backup`：两个按钮不再是"Coming Soon"。
  - **Export Backup**：独占快照锁内导出 → 编码为单个 ZIP → 通过 Blob 链接下载（`veil-backup-<时间>.zip`）。不含 API 密钥。回复正在生成时拒绝。
  - **Import Backup**：选文件（`.zip`，超过 256 MiB 直接拒绝）→ 解码、校验、预检（只读）→ 显示每个域"备份里/本机上"的数量、图片数、阻塞项和警告 → 空设备点 Restore；设备有数据时必须勾选"这会替换设备上的全部内容"才能点 Replace everything → 成功后提示重新加载并重新输入 API 密钥。
  - 卸载或再次操作会取消还在等锁的请求（AbortController）。
- `lib/backup/backup-flow.ts`：以上流程的无界面逻辑（导出、检查、应用、恢复/回滚、错误转为一句话）。
- `RestoreGate`（`app/layout.tsx`）：设备上存在恢复日志（上次恢复/覆盖被中断）时，**不挂载任何 Provider 与启动初始化**（它们加载时会写默认数据，会影响恢复判断），只显示"Restore interrupted"页：回滚，或选同一个备份文件继续。成功后整页重新加载。
- 过期 generation 标记（崩溃遗留）：导出/预检以一句话提示"打开该对话一次再试"（对应总账入口阶段待办），不静默处理。

## 证据与未验证

- 自动化测试：`backup-flow`（导出→文件→空设备导入一致；已有数据走覆盖且一致；blocked 不可应用；非备份文件拒绝且不读设备；中断后回滚/继续；换文件拒绝；消息）7 个；`backup-entry-ui`（jsdom：门禁在有日志时不挂载子树、正常时挂载；设置页导入预览→恢复→再导入需勾选才能替换；无效文件只给提示）4 个；全量 1104 pass / 0 fail，typecheck、lint 0 error、`build --webpack` 通过。
- **未验证（需真机）**：iPhone Safari / 主屏幕 App 里 Blob 下载与文件选择器的实际表现；大备份的内存与耗时；真实浏览器中途被杀后的恢复页；`NEXT_PUBLIC_VERCEL_GIT_COMMIT_SHA` 在 Vercel 是否可用（不可用时 manifest 里 sourceCommit 为 40 个 0）。
- 已知：新装设备启动会写入默认预设/正则/绑定，因此"空环境"在真机上多半表现为"有数据"，会走显式覆盖路径（有安全副本，结果相同）。
- 遗留孤儿安全副本（删除失败）无害；本单未做清理入口。
