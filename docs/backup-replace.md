## 做什么

`replaceWithBackup(manifestJson, files, device, locks, { confirmed })`（`lib/backup/restore.ts`）：把有数据的设备整体替换为备份内容。**不是合并**：每个单元整体替换，备份里没有的域会被清空。

- `confirmed` 必填：用户看过的预检报告。独占锁内重新预检，设备变化则 `preview-changed`；设备本来就是空的则 `not-empty-restore`（应走空环境恢复）。
- 写入前把当前设备完整保存到独立数据库 `veil-restore-safety-v1`（`lib/backup/safety-copy.ts`），含本机 API 密钥（只在本浏览器内，仅为原样还原；备份文件仍不含密钥）。保存失败则一个字节都不写。副本先于日志写入。
- 日志 `kind: "replace"` 记录目标摘要与覆盖前摘要。写失败/核对失败：用安全副本把每个单元放回覆盖前状态，核对一致后删日志和副本。
- 回滚/继续只动"覆盖前状态"或"备份状态"的单元；其他内容抛 `target-changed`，不覆盖。安全副本缺失或与日志不符：回滚拒绝（`safety-copy-missing`）并保留日志，仍可用同一个包继续（`recoverRestore("resume")`）。
- `recoverRestore` 同时处理两种日志。空环境恢复的回滚行为不变（31 个既有测试仍通过）。

## 证据与未验证

- 自动化测试（fake-indexeddb，模拟数据）：15 个。覆盖替换结果与干净恢复一致；4 个有差异的单元各两种故障注入（含"写入后报失败"）后设备与 API 密钥原样还原；中断后回滚/继续；安全副本缺失/保存失败；未确认、预检过期、空设备；他人改动不被覆盖。
- 未验证：真实浏览器中途被杀、安全副本的存储配额（大图片）、其他标签页的旧内存状态（第 8 阶段需重新加载）、Safari/iOS。
- 遗留孤儿安全副本（删除失败）无害，第 8 阶段启动检查可顺带清理。
